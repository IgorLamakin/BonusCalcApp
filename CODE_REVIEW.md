## 1. Что сделано хорошо (это стоит сохранить)

1. **Правильный каркас безопасности Electron**: `contextIsolation: true`, `nodeIntegration: false`,
   preload с явным белым списком каналов (`preload.js:6-20`), блокировка навигации и `window.open`
   (`main.js:123-134`), CSP без inline-скриптов (`index.html:7-8`).
2. **История рендерится только через DOM API**, без `innerHTML` (`renderer.js:271-337`) — XSS через имя
   компании/менеджера закрыт осознанно и с комментарием.
3. **Валидация данных на границе IPC**: `toNum`/`sanitizeCalc` (`main.js:59-98`) — числа ограничены,
   строки обрезаны, управляющие символы и `<>` вырезаны.
4. **Экранирование имён файлов** при экспорте (`safeName`, `main.js:216,285`) — не падает на `ООО "Альфа"`.
5. **Дедупликация истории** вместо тупого `unshift` (`main.js:153-186`) + лимит 100 записей — приятная деталь.
6. **PDF с кириллицей**: шрифт Roboto подключён и регистрируется (`main.js:301-305`) — типичная проблема решена.
7. **Ноль лишних зависимостей**: только `exceljs` + `pdfkit`, генераторы иконок написаны на чистом Node,
   `package-lock.json` закоммичен, есть LICENSE/README/CHANGELOG по Keep a Changelog.
8. **Продуманный UI**: кастомный слайдер с заливкой, toast, пустое состояние истории, Enter и Ctrl+Enter,
   аккуратные мелочи вроде `error`-обработчика логотипа.

Вывод: база хорошая. Проблемы — прикладные и инженерные, а не «всё переписать».

## 2. Блокеры релиза (P0)

### 2.1. В установщик уезжает мусор и внутренняя конфигурация

`files: ["**/*", "!dist/*", "!*.log"]` (`package.json:30-34`) — это «всё, что есть в папке».
Собранный `dist/win-unpacked/resources/app.asar` = **108,9 МиБ**, установщик — **138,7 МиБ**.
Внутри (замер по заголовку asar):

| Содержимое                                                                   | Размер       | Зачем в релизе                       |
| ---------------------------------------------------------------------------- | ------------ | ------------------------------------ |
| `BonusCalc-1.0.0-backup.exe`                                                 | **64,4 МиБ** | не нужно (59 % asar)                 |
| `*.map` (exceljs, fontkit)                                                   | **19,1 МиБ** | не нужно                             |
| `node_modules/pdfkit/.yarn/…`                                                | 3,6 МиБ      | не нужно                             |
| `.opencode/agents/b24cowork.md`, `.opencode/openwork.json`, `opencode.jsonc` | ~4 КиБ       | **утечка внутренней инфраструктуры** |
| `background.jpg`, `icon.png` (357 КБ), `make-icon.js`, `process-logo.js`     | ~1 МиБ       | не нужно в рантайме                  |

В `b24cowork.md` лежит системный промпт внутреннего агента («Битрикс24 Коворк/Код»), в `opencode.jsonc` —
адреса MCP-серверов, имя переменной `B24_COWORK_MCP_TOKEN` и id memory-проекта. Самих секретов нет,
но это внутренняя кухня, которая не должна скачиваться с GitHub Releases.

**Исправить:** заменить `**/*` на явный whitelist (`main.js`, `preload.js`, `index.html`, `renderer.js`,
`font.ttf`, `assets/**`, `LICENSE`), добавить `!.opencode/**`, `!opencode.jsonc`, `!**/*.map`,
`!**/.yarn/**`, `!*.exe`, `!*.jpg`, `!make-icon.js`, `!process-logo.js`.
Итог: asar ~22 МиБ, установщик меньше примерно на 80 МБ (оценка).

### 2.2. Excel-отчёт «Расчёт 1» формируется с ошибкой (проверено прогоном)

`main.js:212-278` смешивает `addRow` и жёстко прописанные номера строк. Воспроизвёл код на реальном ExcelJS:

```
 8 "Ставка НДС"            | "20%"
 9 "Налог на прибыль"      | "20%"
10 "РЕЗУЛЬТАТЫ РАСЧЕТА"    | "30%"   ← заголовок затёр подпись «Процент премии»
15 "Чистая прибыль"        | 160000  ← <BOLD> поставить здесь не нужно
16 "ИТОГОВАЯ ПРЕМИЯ"       | 48000   ← а нужно здесь
```

То есть в отчёте пропадает ставка премии, а жирным выделена не итоговая строка. В «Расчёте 2» повезло —
там `lastRow` попал в цель случайно.

**Исправить:** строить лист последовательно, запоминать фактический номер последней строки
(`ws.lastRow.number`), а не хардкодить 9/10/14/15. Заодно убрать дублирование строки «Маржа» в margin-режиме.

### 2.3. Сборка не воспроизводится из чистого клона

`build/` в `.gitignore` (`.gitignore:6`), но `win.icon`, `buildResources` и `nsis.*Icon` ссылаются на
`build/icon.ico` (`package.json:28,44,55-56`). В git файла нет → после `git clone` + `npm i` + `npm run dist`
сборка останется без иконки (а `npm run icon-default` вообще не создаёт `.ico`, а `process-logo.js` пишет
в `build/` без `mkdir` и упадёт, если папки нет).

**Исправить:** либо коммитить `build/icon.ico`, либо `"prebuild": "node process-logo.js"` + `fs.mkdirSync(..., {recursive:true})`
в обоих генераторах; `make-icon.js` должен тоже собирать `.ico`.

### 2.4. Electron 25 — вне поддержки, плюс уязвимости в prod-дереве

`electron ^25.9.8` (Chromium 114) — ветка снята с поддержки ещё в 2023 году, security-патчей не получает.
[График поддержки Electron](https://releases.electronjs.org/schedule) — сейчас актуальна совсем другая мажорная ветка.

`npm audit --omit=dev` даёт 3 уязвимости: `brace-expansion` (high, DoS через exceljs→archiver→readdir-glob),
`uuid` (moderate, через exceljs). Реально эксплуатировать в этом приложении их негде, но чистить нужно.

**Исправить:** обновить Electron до поддерживаемой ветки, `overrides` для `brace-expansion`/`uuid` или обновление
`exceljs`. Отдельно: `exceljs` занимает 20,6 МиБ ради одного листа — при желании заменяется на лёгкий writer.

## 3. Функциональные баги (P1)

**3.1. Нельзя ввести 0 %.** `parseFloat(el.value) || 20` (`renderer.js:101-106` и `109-117`): при вводе `0`
результат `0` — falsy → подставляется 20 %. То есть нулевая ставка НДС/налога недостижима, и пользователь
не поймёт, почему. Исправить на `Number.isFinite`.

**3.2. Экспорт может выгрузить не то, что на экране.** В рендерере один глобальный `lastCalculation`
(`renderer.js:12`), перезаписываемый обеими панелями. Сценарий: посчитали «Расчёт 1» → перешли на «Расчёт 2»
и посчитали → вернулись на вкладку 1, жмём Excel/PDF — выгрузится **расчёт 2**, хотя на экране расчёт 1.
Кнопки не сбрасываются при переключении вкладок. Исправить: два независимых снимка (`state.calc1`/`state.calc2`)
и сброс disabled при правке полей.

**3.3. Двойное хранение настроек.** Ставки пишутся и в `localStorage` (`renderer.js:66-83`), и в
`settings.json` через main (`main.js:201-209`). При старте сначала применяется localStorage, затем асинхронно
перезаписывается данными из main (`renderer.js:405,482-488`) — источник правды один, но фактически их два,
и при расхождении «мигают» значения. Плюс `saveDir` объявлен в `DEFAULT_SETTINGS` (`main.js:15`), но нигде не
используется: диалоги всегда открываются в Downloads. Мёртвая настройка.

**3.4. «Очистить историю» — без подтверждения и без undo.** `renderer.js:363-368`: один клик стирает до 100
записей, toast «История очищена» показывается независимо от результата промиса. Деструктивное действие
обязательно требует `dialog`-подтверждения (лучше — в main) и, в идеале, экспорта перед очисткой.

**3.5. Риск тихой потери истории.** `saveHistory` пишет `writeFileSync` прямо в `history.json` (`main.js:51-57`).
Обрыв питания/антивирус/крэш в момент записи → битый JSON → `loadHistory` вернёт `[]` (`main.js:40-49`) и
история «исчезнет» без сообщения. Исправить: запись в `.tmp` + `rename`, держать `history.json.bak`,
при ошибке парсинга — восстанавливаться и сообщать пользователю.

**3.6. Два экземпляра приложения затирают историю.** Нет `app.requestSingleInstanceLock()`. Открыли два окна —
оба пишут в один файл, побеждает последний. Добавить lock + фокус на существующее окно.

**3.7. Молчаливые ошибки экспорта.** `renderer.js:191-203,257-269`: `.then(toast)` без `.catch` → unhandled
rejection, пользователь не видит ничего. `dialog.showSaveDialog()` вызывается без родительского окна
(`main.js:219,288`) — диалог не модальный, окно уходит под приложение. Передавать `BrowserWindow.fromWebContents(event.sender)`.

**3.8. Валидация UI — декоративная.** `showFieldError` (`renderer.js:120-128`) ни разу не вызывается с `true` —
мёртвый код. `min="0"` не мешает ввести отрицательное значение с клавиатуры, `1e400` даёт `Infinity` в расчёте,
вставка «1 000» превращается в 1, `parseFloat('1,5')` = 1 (запятая как разделитель не работает). Нужен
нормализатор ввода (запятая/пробелы → точка, отсечение мусора) и реальная подсветка ошибок.

**3.9. Загрузка из истории считает по текущим ставкам.** `applyHistory` (`renderer.js:339-361`) восстанавливает
суммы и процент премии, но не `vatPercent`/`incomeTaxPercent`, хотя они показаны в карточке. Результат после
загрузки может не совпасть с сохранённым — и это выглядит как «баг калькулятора».

**3.10. Мелочи, которые заметит пользователь:** слайдер жёстко ограничен 1–50 % (`index.html:611,674`) —
больше 50 % ввести нельзя, 0 % — тоже; нет копирования результата в буфер; нет сброса формы; размер/позиция
окна не запоминаются; заголовок окна «Калькулятор премии Pro» (`main.js:116`) против `productName`
«Расчет рентабельности» и `<title>Калькулятор премии</title>`; дефолтное английское меню Electron и DevTools
доступны в проде.

## 4. Методика расчёта НДС (согласована: оставляем как есть)

Сейчас (`renderer.js:150-155,220-224`):

```
маржа          = выручка − закупка − логистика       // все суммы «с НДС»
НДС            = маржа × ставкаНДС
прибыль до нал = маржа − НДС
налог          = прибыль до нал × ставкаНалога
премия         = чистая прибыль × процентПремии
```

Проблема: если все входные суммы уже **с НДС**, НДС нельзя начислять сверху на маржу — его нужно
**извлекать** из выручки и закупки. Для выручки 1 200 000, закупки 600 000, логистики 0 и НДС 20 %:

|                         | Сейчас      | Стандартная бухгалтерия |
| ----------------------- | ----------- | ----------------------- |
| НДС к уплате            | 120 000     | 100 000                 |
| Прибыль до налога       | 480 000     | 500 000                 |
| Налог на прибыль (20 %) | 96 000      | 100 000                 |
| Чистая прибыль          | 384 000     | 400 000                 |
| Премия (30 %)           | **115 200** | **120 000**             |

Разница в премии ~4 %. Если текущая формула — это согласованная внутри компаний методика («НДС сверху»),
всё нормально, и надо просто зафиксировать это в README, чтобы вопросов не возникало. Если нет — отчёты
считают не то, что ждёт бухгалтерия.

**Решение (10.11.2026): остаётся текущий вариант «НДС сверху на маржу».** Значит, менять формулу не нужно —
достаточно описать её в README и подписать в интерфейсе, а в шаге 2 закрепить текущую методику тестами
(чтобы её случайно не «починили» при рефакторинге).

## 5. Что можно сделать лучше (P2/P3)

**Безопасность и платформа**

- `sandbox: false` (`main.js:112`) обоснован в CHANGELOG тем, что «`sandbox: true` блокировал contextBridge».
  Это неверно: в sandbox-режиме preload по-прежнему может использовать `contextBridge` и `ipcRenderer`
  (недоступны только `fs`/`path`, а preload их и не использует) — можно включать `sandbox: true`.
- Формулы живут только в рендерере, main принимает готовые `vat/netProfit/bonus` по IPC и просто пишет их в отчёт.
  Логичнее: чистый модуль `calc.js`, один и тот же в рендерере и в main; main пересчитывает из входных данных.
- Нет `app.setAppUserModelId`, нет обработки `render-process-gone`/`uncaughtException`, нет `removeMenu()`
  в проде, нет автообновления, нет подписи кода (SmartScreen).
- `partition: 'persist:bonuscalc'` — лишняя кастомная сессия, без неё проще.
- PDF: если `font.ttf` не найден, тихо рендерит Helvetica → кириллица ломается; нет контроля переполнения
  страницы при длинном названии компании. Лицензия шрифта: `font.ttf` — Roboto 3.015 под **SIL OFL 1.1**,
  текст лицензии в репозитории отсутствует (OFL требует распространять его вместе со шрифтом) → добавить
  `LICENSES/Roboto-OFL.txt`.

**Код и структура**

- `index.html` — 729 строк с inline-CSS, `renderer.js` — 501 строка; панели 1 и 2 почти полностью дублируются
  (`paintSlider`/`paintSlider2`, `calculate`/`calculate2`, `exportExcel`/`exportPdf`/их двойники, два набора
  полей ставок). Свести к одной разметке-шаблону + конфигу режима: минус ~250 строк и минус целый класс
  расхождений между панелями.
- Вынести CSS в `styles.css`, JS панелей — в модули; структура `src/main/…`, `src/shared/calc.js`,
  `src/renderer/…`, `tests/`.
- Дублирование генераторов иконок (600 строк ручного PNG-кодека) — оставить можно, но добавить `.ico` в
  `make-icon.js` и `mkdir` в `process-logo.js`; PNG-кадры мелких размеров в `.ico` лучше писать как BMP
  (Windows местами показывает PNG-кадры <256 px пустыми).

**Процесс**

- Полное отсутствие тестов при денежной логике — самый большой риск проекта. Нужны unit-тесты формул
  (округление, 0 %, отрицательная маржа, границы) и smoke-тест экспорта.
- Нет ESLint/Prettier, нет CI (`.github/workflows`), нет `engines` (README обещает Node 18+, а
  `electron-builder@26` требует 20+).
- Расхождения в названиях (`raschet-rentabelnosti` / «Расчет рентабельности» / «Калькулятор премии Pro» /
  «Калькулятор премии») и мусор в корне: `BonusCalc-1.0.0-backup.exe`, `start_err.log`, `start_out.log`,
  `background.jpg`.
- Нет поля версии схемы данных (`schemaVersion`) в `settings.json`/`history.json` — будущие миграции делать нечем.
- Нет экспорта/импорта истории (перенос между машинами сейчас = ручное копирование файлов).
- `dist/builder-effective-config.yaml` показывает `signAndEditExecutable: false` — последняя сборка шла в
  portable-режиме, поэтому метаданные/иконка exe не вшиты.

Важно: `.gitignore` уже исключает `.opencode/` и `opencode.jsonc` — **в репозиторий на GitHub они не попадают**.
Проблема в другом: `electron-builder` игнорирует `.gitignore` и берёт из папки вообще всё. Поэтому они оказываются
в установщике, который скачивают пользователи. Как только в `package.json` появится явный список нужных файлов — весь
этот мусор исчезнет из сборки автоматически, сами файлы можно оставить на месте.

## 7. План работ

Разбивка ниже — это просто **очередь работ по риску**: сначала быстрое и безопасное, потом то, что требует
переделки кода. «Этап 0» = первый заход, самый короткий.

### Шаг 1. Быстрые исправления, не меняющие архитектуру («этап 0» из прошлой версии плана) — 0,5–1 день

1. Whitelist в `files`, исключить бэкап-exe/`.opencode`/`opencode.jsonc`/`*.map`/`.yarn`/служебные скрипты.
2. Переписать построение Excel-листа (последовательно, без хардкода строк); убрать дубль «Маржа».
3. Починить сборку иконок: `build/icon.ico` в git **или** `prebuild`-скрипт + `mkdir` + `.ico` в `make-icon.js`.
4. `parseFloat(...) || 20` → корректный разбор (0 % сохраняется).
5. Раздельное состояние для экспорта (расчёт 1 / расчёт 2), сброс кнопок при правке полей.
6. Подтверждение очистки истории + `.catch` на все промисы экспорта + модальные диалоги с родительским окном.
7. `requestSingleInstanceLock` + атомарная запись JSON (tmp→rename) + `.bak` и восстановление.
8. Вычистить корень (`BonusCalc-1.0.0-backup.exe`, логи) — бэкап перенести в релизные артефакты, не в папку сборки.

**Приёмка:** `npm run dist` даёт установщик < 90 МБ; xlsx из «Расчёта 1» содержит «Процент премии» и жирную
«ИТОГОВАЯ ПРЕМИЯ»; ставка 0 % принимается; экспорт после переключения вкладок соответствует видимым данным;
история не теряется при имитации битого файла.

### Шаг 2. Денежная логика: один расчёт и тесты — 1–2 дня

1. `src/shared/calc.js` — чистые функции расчёта + 20–30 unit-тестов на `node:test` (без новых зависимостей).
2. main пересчитывает результат из входных данных (не доверяет рендереру).
3. Настройки — только в `settings.json` (убрать `localStorage`, мигрировать значения), `saveDir` либо
   реализовать, либо удалить.
4. Нормализация и валидация ввода (запятая/пробелы, отрицательные, диапазоны), включить `showFieldError`.
5. `schemaVersion` в данных, бэкап истории, загрузка записи вместе с её ставками.
6. `LICENSES/Roboto-OFL.txt`.

**Приёмка:** `npm test` зелёный; изменение ставки в любой панели синхронно отражается в обеих; загрузка записи
из истории даёт ровно тот же результат, что был сохранён.

### Шаг 3. Платформа и порядок в проекте — 2–4 дня

1. Electron 25 → поддерживаемая ветка + `sandbox: true` + регресс-прогон экспорта.
2. `overrides`/обновление зависимостей, `npm audit` чистый (минимум — без high).
3. ESLint + Prettier, скрипты `lint`/`format`, CI на GitHub Actions (install → lint → test → build на
   `windows-latest`, артефакт установщика).
4. Разбить `index.html` (styles.css, модули), унифицировать панели 1 и 2.
5. `setAppUserModelId`, меню/скрытие DevTools в проде, отключение лишней сессии, `engines.node >= 20`.
6. Единые название/версия/терминология в UI, README, CHANGELOG.

**Приёмка:** CI зелёный на PR; собранный установщик ставится и экспортирует Excel/PDF; аудит без high.
